# i18n

The web app ships three catalogs under `apps/website/src/i18n/locales`: `en`, `zh-CN` and `zh-TW`. English is the reference catalog.

## The gate

`apps/website/src/i18n/locales.test.ts` fails when:

- a key is used in source but missing from a catalog
- a dynamic key call site has no entry in `DYNAMIC_KEYS`
- a `DYNAMIC_KEYS` entry has no matching call site
- a dynamic key is not defined in the catalogs
- a catalog key is not used by any source file
- a full key written in a script array or record is not defined
- a key is missing from a catalog, or its `{placeholders}` or list length differ
- a translated value, including any list element, is identical to English outside the explicit allowlist
- a message is empty
- a key does not resolve at runtime
- a template has literal text or a literal `placeholder`, `title`, `aria-label` or `alt`
- a script or template contains a CJK literal

`vp check` cannot carry this rule: oxlint does not read `.vue`, and a rule only sees the one file it runs on. The test parses SFCs with `vue/compiler-sfc`.

`DefineLocaleMessage` is not the gate. `vue-i18n`'s `t` accepts `Key extends string`, so a probe with `t('definitely.missing.key')` compiled clean under `tsc` 7.0.2. The test is the enforcing check.

## Adding a string

1. Add the key to all three catalogs.
2. Call `t('namespace.key')` with a literal key. Do not call `t(variable)`.
3. If the key is selected from data, keep the possible keys as full literals in a script array or record, then add the exact keys its call site can produce to `DYNAMIC_KEYS` in `locales.test.ts`. The test names the unmatched call site, and the literal check validates each full key.
4. Run `vp test src/i18n/locales.test.ts`.

Never build a key from an unchecked string. The test rejects the call site until its key set is written down.

## Runtime language

`useLangQuery()` owns the active locale. Resolution order: native `lang`, the URL (`#/...?lang=` first, then the outer `?lang=`), the tab's stored choice, `navigator.language`, then `en`. Regional tags map onto the catalogs: `zh-Hant`, `zh-TW`, `zh-HK` and `zh-MO` become `zh-TW`, other `zh-*` become `zh-CN`, and `en-*` becomes `en`. The URL value seeds the first render only; later changes come from native or the picker.

The home page shows a language picker only when native supplied no language, so the App keeps ownership of its own language. The active locale also sets `document.documentElement.lang` and `document.title`.

## Cloudflare

`apps/website/wrangler.jsonc` deploys the built `dist` as Workers static assets. `worker/index.ts` proxies `/v2/*` to `https://api.voischat.cn`. The proxy is not optional: the app calls `/v2` relatively and the API returns no CORS headers.

```sh
vp run website#deploy   # build with ~/.vois/.env, then wrangler deploy
```

The local wrangler token exposes one account, displayed as `Kvoon@duck.com's Account` (`28a23c2ec9aeeb01a95276f1d9ca42df`), with workers.dev subdomain `kvoon`. The config pins that ID. If KVOON9 is a separate Cloudflare account, change `account_id` before deploying. The worker is `vois-app-webview` at https://vois-app-webview.kvoon.workers.dev. The build needs `VITE_APP_ID` and `VITE_APP_KEY`; locally they come from `~/.vois/.env`, and a CI deploy must inject them as secrets.

The standalone page has no native bridge. The home page and static screens render without it; data screens show their own auth or network error state.
