# 设备管理：现状与缺口（唯一现状文档）

> 2026-11-10。本文只描述**当前 main** 上的实际状态；历史计划、逐屏清单与验证细节见文末索引。
> 状态：设备管理的 H5 复刻与 native UI/UX 对齐**已并入 main 并推送**（`714668c`）；充值续费 lane（按设备微信支付、待续费设备入口）已并入 main。

## 已完成（按屏，数值为实测）

### 设备列表

- 根 tab 页**无返回键**；「已连接设备」分组标题下逐行列设备，行 = 头像 + 昵称 + 型号，整行可点。Header 右上角「待续费设备」进入待续费列表，始终显示。

### 设备详情

- 标题固定「设备详情」；头部 = 头像（半透明白盘 + 不透明铅笔角标，60% 白底，群详情为 60% `bg-primary`）+ 昵称（重命名铅笔）+ 激活时间小字。
- 四张卡：信息卡 / 管理卡 / 位置卡（共享位置开关领行）/ 解除绑定卡；**卡间距 12**，信息行 **36**，菜单行 **56**。
- 解除绑定是**红字行**，弹窗「提示 / 是否解除绑定设备？ / 取消 · 确定」。
- 菜单能力门控已落地（详情口径）：按 `device-get-detail` 的 `location_support` / `reminder_support` 隐藏 共享位置 行与 提醒 行（缺字段视为支持）；`manager-get-all-device` 的相反值已无消费者。
- 返回键 44×44，`left: 28`（与全站一致，见「全局」）。

### 联系人管理

- 入口卡两行，入口行高 **60**；「已加入」标题在卡内 **8px** 内边距处；空卡**填满视口**。
- 行 = 头像 + 昵称 + 箭头，按**拼音排序**（`localeCompare('zh-Hans-CN')`）。

### 从通讯录添加 / 按条件查找添加

- 搜索框高 **48**，行高 **64**，行内只有名称 + 勾选；已添加行标「已添加」并禁用。
- 申请理由**可编辑**，默认文案每次打开对话框重置。

### 紧急联系人

- 顺序：提示（配额与剩余 SOS 次数为**红字**）→ 添加卡（微喇联系人 / 电话联系人）→ 已加入卡。
- 添加微喇联系人只列**设备联系人**（`friend-get-all`）：接口对非设备好友返回 `300 不是好友`；设备没有联系人时显示「暂无可添加的好友。」并提示先去联系人管理邀请。
- 加电话页 = 方形插图占位 + 两个圆角输入 + 灰字提示 + 全宽保存。

### 能力显隐（原生对照，2026-11-13）

- 原生决定菜单显隐靠的是 socket 设备配置（`location_support`、`reminder_support`、`emergency_forbid` 等），不是 `/v2` 接口；可行性文档 A2 记录了把这些字段加进 `device-get-detail` 的需求，后端未交付前 H5 只能按现有 HTTP 字段猜。
- 实测两台设备（同一 App 与同一 H5 账号对照）：ZX05 的 `device-get-detail` 给出 `location_support: false`、`reminder_support: false`，原生详情页隐藏位置与紧急联系人入口；CF03（疯狂星期五 账号）的 HTTP 字段是 `location_support: true`，但原生详情页同样隐藏三个位置入口，且 `track-get-mode` 返回 `errcode 20 参数错误`——说明 HTTP 的 `location_support` 与原生判断并不一致。
- 因此 H5 侧的处理是**让页面容错**而不是猜入口：`track-get-mode` 失败不影响位置页的地图、围栏与当天轨迹，仅不出底部警告；紧急联系人按双零配额显示不支持。

### 位置 / 围栏

- 位置页右侧**圆形按钮**（添加围栏 / 修改围栏），实时位置 pill **顶部居中**（`max-w: calc(100% - 8rem)`，与围栏按钮留 62px 间隙 @375 / 34px @320），低频警告在底部；设备位置 = 当天轨迹最后一点。
- 无围栏时先弹**添加围栏确认弹窗**，已有围栏直接进编辑器。
- 围栏编辑器：顶部 **− / 200 米 / 滑杆 / 1000 米 / +**（步长 50，夹取 200–1000，默认 300）；「围栏中心」显示**逆地理地址**；底部**全宽保存**；已有围栏才有**删除围栏**。

### 轨迹

- 进入即弹日历（今天预选、**未来日期禁选**），确认后才出现右上 `M/d` 徽标。
- 空日提示是**底部 toast**（约 2.6 秒自动消失），不是常驻浮层；**跳点过滤**按 100 m/s 双跳判定丢弃 GPS 尖刺。

### 轨迹上报设置

- 单卡四行（关闭 / 低频 / 中频 / 高频），右侧 radio，选中即写 `track-set-mode`。

### 提醒

- 编辑页行序：**重复 → 内容 → 时长 → 次数 → 间隔**；列表字号 **24 / 16 / 14**（时间 / 内容 / 重复）。
- 内容为空点「确定」弹**两按钮**对话框（去编辑 / 取消），不静默保存。
- 支持**自定义星期**；后端 `repeated_type=3` 的**每月**档保留不丢。

### 充值续费

- 设备列表：header 右上角「待续费设备」进入待续费列表，无论当前是否有待续费设备都显示。
- 详情页：`sim_card` 存在时渲染卡 ICCID / 卡到期时间 / 「流量卡充值记录」入口；`recharge=true` 时加红字「需充值」；不再有「待续费设备」入口。
- 待续费设备：`simcard-get-all-need-renew` 列表（型号 / 设备号 / ICCID / 到期），每条有「续费」按钮；点击后单卡建单 → 确认 → 支付。没有多选、全选或批量建单。
- 建单：`simcard-create-renew-order` 一卡一单，金额按分转元展示；每次「缴费充值」或「续费」都新建订单。
- 支付：建单后走 `/v2/pay/create-wechat-app-order` → `wechat-app-prepay` → `pay-wechat-trade-success`；桥等待 120 秒；5.0.6 不支持时提示升级。Android 旧 WebView 缺 `Object.hasOwn`，由 `apps/website/src/polyfills.ts` 补齐。
- 充值记录：`simcard-get-all-renew-order`，行 = 订单号 / 金额 / 状态 / 时间。
- **未闭环**：真实微信支付成功路径尚未验证；调试卡 `wl301010105341` 返回 42012，测试卡 `wl301010386256` 可建单。iOS 取消支付不回包，页面走 120 秒超时；支付中弹窗有关闭按钮。

### 全局

- 对话框统一「提示 / 确定 / 取消」文案与同一套按钮尺寸。
- 返回键位置统一在 `PageHeader`：44×44，`left: 28`；tab 根页不渲染。
- 头部右侧不再有语言切换 pill；`PageHeader` 右侧是页面自填的 `action` slot（轨迹页放日期选择，提醒编辑页放「确定」）。
