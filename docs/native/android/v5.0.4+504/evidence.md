# Evidence — android-5.0.4+504

Provenance for every factual claim in this directory. Nothing here was executed:
all confidence levels describe static reading of the package, plus the H5 package
where the claim is about the JS side.

## Reproduce

```sh
node docs/native/tools/extract.mjs            # verifies SHA-256, decodes into .tmp/rev/android-5.0.4+504
```

- Package: `vender/WL_V5.0.4_Code504_09181532.apk`, SHA-256
  `ecb1f2a64ad7629bb3bbdb74f6e34f1bc8050348eceb05164299a28a2b581edf`
- Tooling: jadx 1.5.6 (`--no-src` for resources, `--no-res` for sources).
- Spans read in this pass: `classes.dex`, `classes2.dex`, … (the classes cited
  below sit in `classes11/12/14/17/18.dex`), `assets/WebViewJavascriptBridge.js`,
  `resources/AndroidManifest.xml`, `resources/res/layout/*.xml`.
- Optional: the REA Android provider (`inspect_android_package`,
  `search_android_classes`) was **not** used — it needs `REA_JADX_MCP_JAR`
  (jadx-headless-mcp 0.7.1) in the MCP server environment, which this machine
  does not have configured yet.
